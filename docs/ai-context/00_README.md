# 简历生成器：AI 项目上下文包

## 这组文档是做什么的

这不是一份要求 AI “一次性把整个产品做完”的超级 PRD。

这组文档的目标是：

1. 让 AI 明白这个产品为什么存在。
2. 让 AI 明白哪些事情**明确不做**。
3. 固定核心数据结构和模板规则，避免每轮开发都重新发明架构。
4. 把项目拆成小阶段，每次只完成一个可验收结果。
5. 让后续更换 AI、开发者或技术栈时，项目仍然能继续。

---

## 项目一句话定义

这是一个面向中国求职场景的网页简历生成器：

> 用户填写结构化简历内容，系统用少量稳定的网页模板进行排版，用户可以切换模板、调整少量样式，并最终导出稳定的 PDF。

它不是 Word 编辑器，也不是 Office 模板解析器。

---

## 最重要的产品原则

### 1. 内容和模板分离

同一份简历数据可以切换不同模板。

模板不能拥有独立的一份简历内容。

### 2. 模板少而稳定

第一阶段不追求 3000 个模板。

先完成 3 个基础布局，之后逐步扩展到 8～12 个基础布局。

### 3. 原来的 3000 份 Office 模板只是参考资料

它们未来可以用于：

- 视觉风格归类
- 模板灵感
- 统计常见版式
- 挑选值得重建的设计

但 MVP **不读取、不解析、不复刻、不运行这些 Office 文件**。

### 4. 浏览器是唯一排版引擎

简历预览由 HTML/CSS 或等价 Web 技术渲染。

最终 PDF 必须尽量和网页预览一致。

### 5. 用户不能像 Word 一样自由拖拽

用户编辑的是“内容”和少量“样式参数”。

布局由模板控制。

## 推荐阅读顺序

AI 开始工作前至少阅读：

1. `01_PROJECT_CHARTER.md`
2. `02_MVP_PRODUCT_SPEC.md`
3. `03_RESUME_DATA_SCHEMA.md`
4. `04_TEMPLATE_SYSTEM_SPEC.md`
5. `06_AI_DEVELOPMENT_PROTOCOL.md`

做具体页面时，再读：

- 编辑器：`05_EDITOR_UX_SPEC.md`
- 阶段计划：`07_MILESTONES_AND_ACCEPTANCE.md`
- 接收单次任务：`08_TASK_BRIEF_TEMPLATE.md`

---

## 文档优先级

发生冲突时：

1. `01_PROJECT_CHARTER.md` 的边界最高。
2. `03_RESUME_DATA_SCHEMA.md` 与 `04_TEMPLATE_SYSTEM_SPEC.md` 属于核心架构约束。
3. 阶段任务不得突破当前 Milestone 范围。
4. AI 不得为了“更高级”而擅自增加复杂度。

---
