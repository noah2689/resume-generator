# 04｜模板系统规范

## 1. 模板的定义

模板是一个“如何展示 Resume 数据”的渲染组件。

模板不是文档文件。

模板不是 Word 文件。

模板不是截图。

---

## 2. MVP 模板数量

第一个里程碑：

- 1 个模板

第二个里程碑：

- 3 个模板

核心编辑稳定之后：

- 8～12 个基础模板

只有在基础模板稳定以后，才做批量主题变体。

---

## 3. 第一批基础布局

### Template A：简约单栏

特点：

- 姓名在顶部。
- 联系方式在姓名下方。
- Section 全部单栏。
- 标题左对齐。
- 风险最低。

这是第一优先模板。

### Template B：商务单栏

结构仍然是单栏。

差异来自：

- Header 样式。
- 标题装饰。
- 字体层级。
- 分割线。
- 主题色。

用于验证“不同视觉可以共享同一布局”。

### Template C：左右双栏

建议：

- 左栏约 30%。
- 右栏约 70%。
- 左栏放基本信息、技能等短内容。
- 右栏放工作、项目、教育等长内容。

双栏只在单栏稳定之后实现。

---

## 4. Template 接口概念

无论技术栈如何，模板输入应类似：

```text
Template(
    resumeData,
    styleConfig
)
```

输出是网页 DOM / Web UI。

模板不得直接请求数据库。

模板不得自己保存数据。

---

## 5. Style Token

模板应尽量通过有限 Token 控制样式。

例如：

```json
{
  "themeColor": "#1F3A5F",
  "fontFamily": "Noto Sans SC",
  "density": "standard"
}
```

内部再映射成：

```text
standard:
body font size = 12
line height = 1.55
section gap = 18
item gap = 10
```

用户不能直接输入这些数字。

---

## 6. 模板变体

未来要让用户觉得模板丰富，可以使用：

**基础布局 × 主题风格**

例如：

```text
简约单栏 + 深蓝
简约单栏 + 黑灰
简约单栏 + 墨绿
简约单栏 + 酒红
```

它们可以在 UI 中展示为不同模板卡片。

但底层仍然共享布局代码。

---

## 7. 字体规则

最重要目标不是“字体多”，而是“字体稳定”。

规则：

1. 模板只能使用字体白名单。
2. 开发和 PDF 环境必须拥有同一字体。
3. 中文字体必须经过 PDF 实测。
4. 不读取旧 Word 模板声明的字体。
5. 缺失字体必须有明确 fallback。
6. 不允许模板临时引用网络未知字体。

---

## 8. 图片规则

头像属于可选数据。

模板负责：

- 是否展示头像。
- 头像形状。
- 头像尺寸。

用户不应该拖动头像到任意位置。

---

## 9. 分页策略

MVP 的原则是：

**先保证不重叠，再追求自动一页。**

第一阶段：

- 内容自然分页。
- 避免模块标题和正文完全断开。
- 禁止重叠。

之后再增加“紧凑模式”帮助减少页面数量。

不要一开始开发复杂的“智能一页算法”。

---

## 10. 模板质量检查

每个新模板至少用下面 3 种测试数据验证：

### Case A：短简历

目标：

- 不显得严重空洞。
- Header 不异常。

### Case B：标准简历

目标：

- 1～2 页正常排版。

### Case C：长简历

目标：

- 可以自然分页。
- 不重叠。
- 不溢出页面外。

---

## 11. 新增模板的验收要求

新增模板必须满足：

- 不修改 Resume Schema。
- 不增加模板专属业务字段。
- 能渲染标准示例数据。
- 空字段不会留下奇怪占位。
- 长文本不会覆盖其他文本。
- PDF 中文正常。
- 切换回来内容完全一致。

否则模板不能合并。
